# 任务生命周期修复与验收（2026-08-15）

## 修复范围

本轮只修改任务生命周期、任务中心错误处理与启动器后端生命周期；未修改光学核心计算公式，未修改冻结的实验验证模块。

## 已修复问题

1. **失败任务“重试”生成幽灵等待任务**
   - 新增 `POST /api/v1/jobs/{job_id}/retry`。
   - 后端持久化可重放提交信息，并在重试时创建新的真实 `job_id`。
   - 前端在后端返回新 `job_id` 前不创建任何“等待中”任务。
   - 新任务记录 `retry_of`，便于追溯来源。

2. **失败任务仍可请求正式结果**
   - 任务状态增加 `result_available` / `retry_available` 等字段。
   - “查看结果”仅在缓存已有结果或 `result_available=true` 时启用。
   - 对 `JOB_RESULT_NOT_AVAILABLE` 做结构化处理，不再把它当作新的计算失败。

3. **失败进度条被错误画满**
   - 失败、取消等终态保留后端最后真实进度。
   - 终态使用状态颜色和文字表达，不再伪造 100% 进度。

4. **后端结构化错误在前端丢失**
   - 新增 `ApiError`，保留 `code`、`stage`、`retryable`、`request_id`、`context` 和原始信息。
   - 用户界面显示中文可理解错误，诊断信息保留错误代码。

5. **重复终态日志**
   - 对短时间内完全相同的任务日志做去重，避免同一失败原因连续重复显示。

6. **长期排队 / Worker 停滞没有保护**
   - 新增任务 watchdog。
   - 支持按任务类型配置排队超时和停滞超时。
   - 超时分别进入 `QUEUE_TIMEOUT` / `WORKER_STALLED`，并标记为可重试。
   - Worker 活动会更新 `last_activity_at`。

7. **GUI 退出会终止由演示启动器拉起的后端**
   - `tools/run_demo.py` 默认把后端作为独立服务保留。
   - GUI 退出后，后端继续运行，后台科研任务不因此中断。
   - 如确需恢复旧行为，可显式传入 `--stop-backend-on-exit`。

8. **前后端版本信息不一致**
   - 共享 `APP_VERSION` 统一为 `1.5.0`。
