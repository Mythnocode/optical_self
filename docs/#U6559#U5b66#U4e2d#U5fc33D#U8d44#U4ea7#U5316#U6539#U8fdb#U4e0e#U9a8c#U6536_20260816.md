# 教学中心 3D 资产化改进与验收（2026-08-16）

## 1. 本轮目标

在 1.5.1 源码上改进教学中心 3D 场景的器件可识别度，同时遵守：

- 3D 模型只负责视觉表达，不作为物理计算输入；
- 继续使用 `ExperimentModel -> sceneBridge -> 3D Visual Layer`；
- 复杂视觉模型不直接参与 Pick；
- 拖动期间不重建物理模型，也不运行高成本 3D 更新；
- 精细模型不可用时必须能退化到旧的 primitive 表达；
- 外部模型进入正式资产库前必须记录来源、许可证、哈希、尺寸和锚点。

## 2. 已完成改动

### 2.1 新增视觉资产层

新增：

- `frontend_pyside/features/teaching/asset_registry.py`
- `frontend_pyside/resources/qml/teaching3d/OpticalAssetNode.qml`
- `frontend_pyside/resources/qml/teaching3d/assets/*.qml`

当前内置精细资产覆盖教学目录全部 19 类器件；多个同类器件复用相同视觉资产，因此实际维护 15 个唯一 QML 资产。

标准方案中原来每个设备只有一个 `#Cube/#Cylinder`，现在分别由 4~7 个低成本 primitive 组合出：

- 激光器：机身、出光筒、发光孔、底座；
- 隔离器：圆柱主体、前后端环、底座；
- 透镜：透明光学片、夹持框、支柱、底座；
- 分束器/PBS：透明分光块、45°分光面、安装座；
- 反射镜：镜面、背板、两个调节旋钮、支柱、底座；
- 光纤五轴架：夹头、纤芯入口、调整台、代表性旋钮、底座；
- 功率探头、相机/光束分析仪、波前传感器等测量设备。

这些模型使用项目自有程序化几何，没有引入外部模型许可证风险。

### 2.2 物理层与视觉层隔离

`_Unified3DBridge.set_scene()` 只向 QML 增加：

- `assetId`
- `assetQml`
- `assetTier`
- `pickX/Y/Z`
- fallback 外观参数

光学计算不读取以上字段。专项测试验证：切换精细/简化模型不会改变 `ExperimentModel.revision`，也不会改变 `evaluate()` 结果。

### 2.3 简化 Pick Proxy

`OpticalAssetNode.qml` 中：

- 精细视觉模型默认不 `pickable`；
- 每个设备只有一个低成本 `#Cube` pick proxy；
- proxy 用 `dragOwner` 指向视觉节点根；
- QML 拖动只改 `localDragPosition`；
- 鼠标释放后才调用 `sceneBridge.moveNodeWorld()` 提交到既有场景模型。

因此以后将程序化视觉资产替换成几十万三角面的 GLB 时，拾取/拖动逻辑仍不需要在复杂 mesh 上执行。

### 2.4 性能保护

- Gaussian 包络的每条活动边从 6 个视觉子段调整为 4 个；
- 标准场景包络对象从约 42 降到 28；
- 拖动设备时继续隐藏 Gaussian 包络；
- `Loader3D` 使用 `asynchronous: true`；
- 新增“精细器件 / 简化器件”切换，出现低性能环境时可直接退化；
- 精细资产加载失败时继续显示 primitive fallback。

当前标准场景工程估算：

- 设备视觉子模型：50；
- pick proxy：10；
- 主光线：7；
- Gaussian 包络：28；
- 精细模式总可见绘制对象估算约 100；
- 简化模式约 60。

这是工程预算估算，不是 GPU RenderStats 实测 draw call。

## 3. 新增资产准入工具

### `tools/validate_teaching_3d_assets.py`

检查：

- 教学器件目录是否都有资产；
- QML 文件是否存在；
- 单资产 Model 数是否超过 Tier 预算；
- 视觉资产是否错误引用 `sceneBridge`；
- 视觉资产是否错误设置 `pickable: true`；
- 资产内是否私自创建 Camera/Light；
- `OpticalAssetNode` 是否只有一个 pick proxy；
- Loader3D / dragOwner contract 是否存在。

### `tools/qml_validate_teaching_3d_assets.py`

真实通过 Qt `QQmlComponent` 创建全部唯一资产，检查 QML 语法/类型加载错误。

### `tools/ingest_3d_asset.py`

为后续公开 GLB/OBJ/STL 等模型提供 staging gate：

- 来源、作者、许可证；
- redistribution/modification 权限；
- SHA256；
- 实际尺寸；
- optical origin / axis / mount origin；
- 使用 `trimesh` 做 geometry probe；
- 检测 Blender/Balsam/glTF Validator 是否可用；
- 只生成 STAGED manifest，不会自动进入运行资产库。

### `tools/benchmark_teaching_3d_scene.py`

检查 bridge 重建成本、对象预算、内存趋势以及视觉切换是否改变物理结果。

### `tools/smoke_teaching_3d_qml.py`

创建真实 `UnifiedTeachingQuick3DView`，检查 QML source 错误、资产节点加载失败状态和当前 renderer API。

### 4.8 完整教学工作台级拖拽：发现并修复真实竞态

独立 3D 组件第一次通过后，又新增：

`tools/validate_teaching_3d_full_workbench.py`

直接实例化 `UnifiedTeachingWorkbench`，让输入走生产链：

`QML MouseArea -> sceneBridge -> _on_node_moved/_on_node_activated -> model -> _refresh_all`

这个测试发现了一个此前单元测试无法发现的问题：

- 旧代码在鼠标 `onPressed` 时立即 `sceneBridge.activate(objectName)`；
- 完整工作台收到该信号后同步刷新 scene / 打开对象抽屉；
- 这会在 3D mouse grab 正建立时重建 delegate，导致拖拽有概率不能提交或状态无法清理。

修复方式：

1. 器件按下时先建立 pick-proxy drag，不同步刷新工作台；
2. 普通单击在 release 时才 activate；
3. 真正拖动时先清空 QML drag state，再同步提交 `moveNodeWorld()`；
4. `_on_node_moved()` 在拖拽完成后再把移动器件设为当前选择。

修复后完整工作台真实验证：`PASS`。

- `lens_1` pick 命中；
- drag started：PASS；
- model `(710, 430) -> (756.41, 591.06)`；
- 拖动距离约 `167.62` scene units；
- revision 前进；
- drag state 清理：PASS；
- QML error：0；
- 普通点击 `lens_2`：仍能选中；
- 普通点击不会错误修改 revision。

这项测试证明不是只有孤立 QML 能拖，而是完整教学中心生产 wiring 也能拖。

## 7. 结论

本轮已从“代码和 offscreen contract 验证”推进到：

`真实 Qt Quick 3D OpenGL 绘制 -> 真实 Pick -> 真实鼠标 Drag -> 生产 Workbench 提交 -> 光路重建 -> 多视角截图 -> RenderStats -> 20 次重开内存检查`

并且完整工作台测试实际发现并修复了一处 **按下即刷新导致 mouse-grab 竞态**，说明这轮验收不是形式测试。

当前版本已经证明：

- 精细视觉资产与物理状态隔离；
- 复杂视觉 mesh 不参与 pick；
- 拖动期间只动局部 visual transform；
- release 后才提交模型；
- 完整教学工作台中拖拽可真实改变模型；
- 普通点击选择语义没有被破坏；
- 真实截图、视角切换和相机交互可用；
- 当前精细资产 draw-call / vertex 仍处于预算内；
- warm-up 后重复进入/退出没有观察到持续线性内存增长。

目标 Windows / GPU 仍应做最终帧率和输入手感验收，但“当前环境没有真实 3D / 没做拖拽和截图”的缺口已经补齐。
