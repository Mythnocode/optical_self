# 最终一体化收敛与验收报告（2026-08-15）

## 1. 本轮边界

本轮在上一版“性能与排版收敛”基础上继续完成状态、AI、教学、证据追溯、演示资产和连续流程验收。仍坚持两条硬边界：

1. 不修改光学物理公式、复场传播公式和耦合效率定义；性能优化只改变执行策略、缓存与预热。
2. 当前 Linux/offscreen 环境不能替代真实 QRhi/GPU 桌面和 Windows/Zemax 环境，因此 Qt Quick 3D 的真实视觉体验、Zemax 联动仍标记为目标环境确认项，不把“代码可创建”写成“体验已验证”。

## 2. 状态正确性与证据追溯

- 增加研究记录（research journal）：正式结果、研究任务、设计修订、明确采用当前模型、参数修改等关键事件会记录方案修订号、项目、来源和任务 ID。
- 研究记录随会话恢复；AI 可回答“为什么最后这样改”“之前做了什么”，依据研究记录而不是聊天猜测。
- 当前模型/当前数据集只恢复用户明确采用且仍存在的 ID；训练新模型不会偷偷替换当前模型；已删除模型不会退回列表第一项。
- 结果继续绑定设计 revision；改变物理输入后旧 Findings/结果进入“需更新”，不能冒充当前结论。

## 3. P0 静默物理 Bug

真实连续流程中发现并修复：Headless 数据集生成适配层曾只读取顶层 `wavelength_nm`。平台项目实际把活动波长保存在 `source.wavelength_nm`，因此 780 nm 页面可能静默回退到 1550 nm 数据集。

修复后：

- `source.wavelength_nm` 为权威回退来源；
- 真实 780 nm 演示数据集基于 780 nm source project 生成；
- 又以 Headless 原生数据集任务真实生成 808 nm 样本，`feature_values.wavelength_nm == 808.0`，状态 completed、样本 valid。

该问题写入 `docs/重要Bug回归检查清单.md` 的 `DATASET-PHYSICS-001`，优先级 P0。

## 4. AI：从聊天框收敛为研究导航器

- 新增研究阶段判断：正式结果缺失/过期/失败、模型未采用/不可靠、SHAP 需要物理复核、已有扫描等状态先判断，再给下一步。
- 一次只保留一个主要动作；动作主要是导航、展开、定位和预填，不自动开始正式仿真/扫描/训练/优化，不自动采用候选或模型。
- AI 能从真实后台 `parameter_grid + response_values` 扫描结果直接计算峰位、峰高、3 dB 宽度和对称性，而不依赖页面先整理成绘图字典。
- 诊断结构固定为“现象 → 优先检查 → 为什么 → 怎样区分 → 怎么验证”。峰位偏移与明显不对称同时出现时，不允许只给“机械零点”单一结论，而会提示参数耦合/扩大范围/第二扫描或二维扫描。
- 模型可靠性门继续有效；差模型不能被 SHAP 包装成物理结论。

## 5. 教学中心：现象怎么理解

新增 `phenomenon_lab.py`，按真实研究现象组织，而不是按教科书术语组织：

- 峰位移动；
- 峰值落在扫描边界；
- 曲线变宽/变窄；
- 曲线不对称；
- 峰位/峰高/3 dB 宽度/对称性怎么看；
- X/Y 不一致；
- 尺寸看似匹配但相位/曲率不匹配；
- F/# 与焦区；
- 透镜间距与最佳焦点联动。

每个主题均给出“看到什么、先怀疑什么、如何区分、怎样验证”，并提供对照趋势演示。教学结果明确标记为教学，不冒充正式仿真结果。

“检查我的当前方案”只把用户送回参数研究并预填相应参数，不自动运行，形成：

`发现现象 → AI 提出线索 → 教学理解 → 参数研究验证 → 正式仿真确认`

## 6. 首页与新手入口

首页增加“你现在想做什么”目标入口：提高耦合效率、为什么效率低、研究某个参数、检查装调、比较实验/仿真、学习一个现象。老用户仍可直接使用左侧模块导航，不强制经过新手流程。

## 9. 真实进度与性能

进度条继续使用后台真实状态：提交阶段使用不确定进度；取得 job ID 后，批量任务由真实 `completed_items / total_items` 驱动。实测 5 点扫描出现 0/5、1/5、3/5、4/5、5/5 并最终完成，不使用前端伪百分比。

最终真实性能探针（当前容器、preview、外部测试 USER_DATA_DIR）：

- health HTTP：约 0.011 s；
- 5 点真实扫描：约 3.64 s；
- 两次模型预测：约 0.018 s、0.017 s；
- 两次 SHAP：约 0.013 s、0.010 s，均命中预制有效缓存；
- 真实 41 点 preview 扫描：约 13.73 s；
- 真实 64 样本、包含空气间隔和装调扰动的 tolerance：约 16.08 s，64/64 有效，阈值达标比例约 73.4%。

这些是本环境实测，不把方案文档的预计 86→22 s、7 min→2 min 等写成已实现结果。

之前实测当前容器 4 线程批量执行反而比串行慢，因此仍保留可配置并行能力，但默认不强开 4 线程；到目标 Windows/比赛机器重新基准后再决定并行度。

代码审计确认上一版已经存在本地 `.npy`/memmap 大数组传输；本轮继续通过 smoke test 验证只读 memmap，不重复包装成“本轮新实现”。

## 10. 真实演示资产

随包资产：

- Random Forest 模型，独立测试 R² = 0.9102，MAE ≈ 0.00104，RMSE ≈ 0.00167；
- 使用模型/数据文件**内容摘要**作为持久缓存签名的 SHAP 缓存；它不依赖 ZIP 解压后的时间戳，fresh USER_DATA_DIR 与最终 ZIP 重解压后第一次相同请求均应直接 `cache_hit=true`；

另外，最终 ZIP 首次复检曾捕获一个仅在“打包→解压”后出现的缓存问题：旧缓存键使用 `mtime_ns`，ZIP 解压改变时间戳后首个 SHAP 请求无法命中。现已升级为内容摘要缓存键，并验证“只改时间戳/复制位置仍命中，修改 manifest 内容立即失效”。该问题已加入 `PERF-CACHE-001` 永久回归项。

`tools/build_demo_assets.py` 支持：

- `quick`：真实生成 64 样本 + RF + SHAP + 41 点扫描 + 64 样本容差；
- `full`：按性能方案真实生成合计 1700 样本的标准精度数据、模型/SHAP、41 点扫描、200 样本容差和优化示例；完整模式必须由目标机器显式执行，可能耗时数小时。
