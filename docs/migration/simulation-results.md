# Simulation result presentation checkpoint

Branch: `js`. The complete migration remains in progress.

## Implemented

- Dedicated ray layout, spot, coupling and wavefront result pages consume completed simulation jobs. Header metrics and diagnostic text use the original Python formatting.
- Original array transport, ray adapters, engineering scene data, coupling/wave adapters and labels moved into `shared_presentation`. Qt compatibility facades preserve their existing imports. Display preferences use request-scoped ContextVar values; the Qt facade supplies its existing QSettings preferences.
- `POST /api/v1/simulation/jobs/{job_id}/presentation` materializes trusted job arrays and returns the requested plot. It imports no Qt UI. Missing job returns 404; a training job returns 422.
- Canvas reproduces the original scatter/ray axes and fast heatmap presentation. Original surface artist geometry and contour row sampling remain in Python. JS does not recompute optical results.
- The ray layout retains ResultDocument's existing display convention: the final table thickness supplies the image gap, even when the submitted calculation has a separate image distance. Only display coordinates use this convention.
- Submission snapshots persist with the job identity. Subsequent edits mark the result stale and preserve its submitted geometry. Observation settings update the detector overlay without submitting a calculation.
- Text details, a 900 × 620 in-page enlargement dialog and PNG export are connected. Electron has a restricted PNG save IPC with sender, size, data-URL and signature validation. Canvas export redraws at 220/100 scale rather than enlarging a screenshot.
- The lazy Three.js 3D result renderer now consumes the original pure Python scene primitives. Lens surfaces/bodies, beam envelope, waist, image plane, detector, fiber, labels and initial orthographic projection are shared with Qt. Fat lines reproduce the original point-based line widths; transparent polygons follow Matplotlib's collection/face ordering.
