# 光学仿真计算核心：Python 版 vs C++ 原生版对比与优化总结

本报告系统梳理了本项目光学计算核心（光线追迹与表面物理求解器）从 **Python 实现** 到 **C++ 原生内核（Native Core）** 的演进历程，深入对比两者的架构设计、技术实现、物理语义覆盖度，并对 C++ 优化后的关键性能指标、数值保真度以及工程优势进行全面总结。

---

## 1. 背景与核心痛点

在系统进行大规模数据集生成（Dataset Generation）、多维参数扫描（Parameter Sweep）以及光学系统逆向优化（Optimization）时，仿真管线的耗时构成了核心瓶颈。

### 1.1 Python 版本的性能瓶颈
在最初的纯 Python 追迹路径（`optical_core.physics.geometric.solvers.scalar_raytrace.trace_single_ray_detailed`）中：
1. **全局解释器锁（GIL）瓶颈**：单样本追迹热路径由纯 Python 编写，约占整个仿真流程总耗时的 **90%**。由于 CPython GIL 的存在，多线程不仅无法利用多核 CPU 加速，反而因为高频的线程上下文切换与锁争用导致“开 4 线程比单线程更慢”。
2. **高频小对象分配与 GC 压力**：追迹过程中需要逐光线、逐表面遍历。每根光线在每个表面交互时，频繁构造 `Ray` dataclass 实例、包含 20 多个诊断字段的 `surface_interactions` 字典，并伴随大量微小 NumPy 数组切片，产生了极高的动态内存分配与垃圾回收（GC）开销。
3. **复杂物理模型计算开销大**：包含非球面/圆柱面的牛顿-拉夫逊（Newton-Raphson）迭代求交、多层光学薄膜特征矩阵传输（$2 \times 2$ 复数矩阵连乘）、Fresnel 偏振分解、表面粗糙度与吸收衰减等，纯解释执行效率极低。

### 1.2 NumPy Compact 矢量化方案的局限
为了规避 Python 循环，项目此前探索了基于 NumPy 数组广播的矢量化追迹（`compact_batch_raytrace.py`）：
- **优势**：对简单共轴无镀膜系统大幅提速（追迹时间降至亚秒级）。
- **致命缺陷**：无法支持复杂光学系统。当遇到**多层光学镀膜（Coating Layers）**、**倾斜与偏心位姿变换（Decentered / Tilted Surfaces）**、**光栅表面（Gratings）**等真实工程需求时，NumPy 矢量化无法展开，必须强制回退到慢速的 Python Full 路径。

因此，研发具有完整物理语义支持、跨平台无依赖、支持多核并行加速的 **C++ 原生追迹内核（`optical_native_core.cpp`）** 成为核心突破口。

## 2. 计算核心全维度对比

项目目前存在三种主要的光线追迹后端：
1. **Python Full Tracer**（`scalar_raytrace.py`）：功能最全但速度最慢的基准参考实现。
2. **NumPy Compact Tracer**（`compact_batch_raytrace.py`）：数组矢量化追迹，仅支持简单系统。
3. **C++ Native Kernel**（`optical_native_core.cpp` + `native_trace.py`）：完整物理保真、多线程高并发的原生内核。

### 2.1 架构与技术特性对比表

| 维度 | Python Full Tracer | NumPy Compact Tracer | C++ Native Core (优化版) |
| :--- | :--- | :--- | :--- |
| **主要源文件** | `scalar_raytrace.py` | `compact_batch_raytrace.py` | `native/optical_native_core.cpp` |
| **执行模型** | 解释型逐光线循环 | NumPy 数组矢量化广播 | 编译型机器码 + 多线程并行 |
| **多线程支持** | 受限 GIL，多线程负优化 | 受限于底层 BLAS，主要是单核向量计算 | 常驻原生线程池，线性多核加速 |
| **多层光学镀膜** | 完整支持（复数特征矩阵） | ❌ **不支持**（遇到强制回退 Python Full） | 完整支持（原生复数矩阵快速运算） |
| **表面位姿变换** | 完整支持（3D 偏心与倾斜） | ❌ **不支持**（仅支持共轴理想平面/球面） | 完整支持（欧拉角旋转矩阵与偏心变换） |
| **非球面 / 圆柱面** | 支持（牛顿迭代） | 仅支持旋转对称非球面 | 完整支持（内联牛顿迭代求解） |
| **偏振与相位演化** | 完整支持（Jones 矢量） | 标量简化处理 | 完整支持（完整偏振分解与投影） |
| **交互与能耗诊断** | 逐光线逐表面 20 维全量字典 | ❌ 仅输出最终平面数据 | 完整支持（直接写入连续缓冲区） |
| **内存开销** | 极高（海量短生命周期对象） | 中等（中间临时数组开销） | 极低（连续平坦内存，零内循环分配） |
| **接口契约** | 原生 Python 类 | 原生 Python 类 | 标准 C ABI + Python `ctypes` 胶水层 |
| **容错机制** | 抛出 Python 异常 | 仅支持简单场景，其余不支持 | 智能自检 + 失败全自动平滑回退 Python |

## 3. C++ 原生内核的核心优化技术

C++ 版本并非简单的代码转译，而是在算法架构和底层硬件亲和度上进行了针对性深度优化：

### 3.1 基于 Windows 原生 API 的常驻线程池（Resident Thread Pool）
- **痛点**：对于中等规模光线束（如 441 根光线），单根光线耗时仅约数十微秒。如果每个样本临时创建/销毁 `std::thread`，系统内核线程创建与调度开销将抵消计算提速。
- **优化**：在 Windows 平台采用轻量级 `SRWLOCK` 和 `CONDITION_VARIABLE` 实现常驻线程池（上限 32 线程）。主线程分发任务后仅做事件通知，无需重复创建线程；Linux/POSIX 环境保留轻量级并行备选方案。

### 3.2 自适应内联分块机制（Chunking & Adaptive Inlining）
- **任务分块**：采用固定块大小（`chunk_size = 4`）在多线程间采用步进步长分配，实现隐式的工作均衡（Work-Stealing 机制）。
- **小批次自动内联**：当光线总数较少（`threads <= 1` 或 `total_chunks < threads * 2`）时，自动放弃跨线程上下文调度，直接在调用线程内同步内联计算，消除线程同步抖动。

### 3.3 零堆内存分配与平坦连续数组布局
- 摒弃了面向对象中碎片化的类实例与指针跳转。所有光线状态（位置、方向、光程、振幅、偏振、相位等）均在 C 侧展平为连续的一维/二维紧凑浮点数组（`double*`）。
- 几何求交和特征矩阵计算中的向量、矩阵乘法全部使用栈分配临时变量与内联函数（`inline void mat_vec` 等），热循环内部实现 **Zero Dynamic Memory Allocation**，具有极高的 CPU L1/L2 缓存局部性。

### 3.4 纯静态链接与绿色开箱即用
- 使用 MinGW-w64 编译时指定 `-O2 -std=c++17 -shared -static-libgcc -static-libstdc++`。
- 生成的 `optical_native.dll` 不依赖任何外部 Visual C++ Redistributable 或 GCC 动态运行时库，直接随应用或安装包打包分发（固定 SHA256 校验），终端用户环境无需安装 C++ 编译套件。

### 3.5 严格的边界自检与平滑回退策略（Graceful Degradation）
通过 `native_trace.py` 实施分级防护：
- **静态边界过滤**：检测到需要多分叉光线追踪的光栅（Grating）或特殊群延迟展开（`include_group_delay`）时，自动走 Python 路径。
- **运行时动态拦截**：如果遇到曲面求交异常、入射角越界等无法复刻的数值奇点，捕获 `NativeTraceError` 并整批安全回退到 Python Full 求解器，保证业务系统 100% 不崩溃。

## 4. 优化后的实测指标与性能评估

以下指标来源于项目基准测试脚本（`tools/benchmark_native_trace.py`、`tools/benchmark_dataset_backends.py`）及金样库测量报告（`tests/golden/dataset-backends/`）。

### 4.1 追迹热路径微基准测试（Micro-Benchmark）
*测试环境：Intel Core i7-13700HX，441 根光线 $\times$ 8 个带镀膜表面*

| 求解器实现 | 单次执行耗时 | 相对 Python Full 加速比 | 说明 |
| :--- | :---: | :---: | :--- |
| **Python Full Tracer** | ~1540 ms | 1.0× (基准) | 单核执行，受 GIL 锁限制 |
| **C++ Native（单线程）** | ~17 ms | **~90.6×** | 纯语言与编译优化收益 |
| **C++ Native（多线程池）** | ~13 ms | **~118.5×** | 常驻线程池并发加速 |

> **微基准结论**：C++ 原生内核在纯追迹热路径上实现了 **~100 倍** 级别的绝对计算提速。

## 5. 数值一致性与精度保真（Parity）

C++ 优化在实现百倍提速的同时，未牺牲任何仿真计算精度，全套回归测试（`tests/test_native_raytrace_parity.py`）提供了严格的数学等价性证明：

1. **光线几何状态一致性**：
   - 最终位置 `final_positions_mm` 与最终方向 `final_directions` 浮点全等（相对误差在机器浮点精度内）。
   - 光程 `optical_paths_mm`（OPL）相对误差小于 $1.0 \times 10^{-9}$。
   - 逐段折射率、分段距离及光程累加严格相符。
2. **波动与能量物理一致性**：
   - 场振幅（Field Amplitude）、功率权重（Power Weights）、高斯求积权重（Quadrature Weights）数值一致。
   - 包含 20 个字段的逐表面能量诊断（透射/反射/吸收/散射功率及多层膜能量守恒误差）与 Python 相对误差 $< 1.0 \times 10^{-7}$，绝对误差 $< 1.0 \times 10^{-12}$。
3. **光纤耦合端到端指标一致性**：
   - 耦合效率（`coupling_efficiency`）、总耦合效率（`total_coupling_efficiency`）与耦合损耗（`coupling_loss_db`）端到端误差均满足：
     $$\text{Relative Error} < 1.0 \times 10^{-7}$$
4. **有效性与异常分支一致性**：
   - 状态码（`status_codes`）、孔径裁剪判断（`valid_mask`）及终止原因描述（`termination_reasons`）保持 100% 行为等价。

## 6. 核心优势与工程价值总结

### 1. 突破单机吞吐天花板，大幅缩短机器学习训练数据准备周期
在光学逆设计与机器学习代理模型训练中，动辄需要生成数千至数万个复杂透镜组样本。以带镀膜四镜片系统为例：
- 原 Python 方案生成 1000 个有效样本约需 **7.6 小时**；
- 切换为 C++ 原生核心后，总时间压缩至约 **40 分钟**，工程迭代效率获得数量级飞跃。

### 2. 物理功能完备，破除矢量化方案的功能阉割
不同于简化版矢量化算法必须牺牲“薄膜特征矩阵”或“偏振追踪”等物理属性，C++ 方案是 **Full-feature 等价移植**，让高保真物理仿真与极速计算兼得。

### 3. 架构设计高度内聚，对上层无侵入性
得益于 `_try_native_trace` 与 `prefer_native_trace` 的松耦合设计，底层的 C++ 加速对上层应用透明：
- 前端 Web / PySide 界面、机器学习生成器、优化算法无需改动任何接口；
- 仿真结果通过标准的 `TraceBundle` 契约返回，保持了系统整体架构的纯净与稳定。

## 7. 结语与后续建议

C++ 原生计算核心的引入成功解决了长期困扰仿真平台的性能热点，使得单核计算密集与多核并行能力达到生产级标准。

**后续演进建议**：
1. **进一步推进波动光学（Wave Propagation）的 C++ 移植**：在光纤耦合等混合场景中，剩余的 10% 耗时逐渐变为波动传播、重采样与 FFT，可考虑将这部分链路进一步下沉至 C++ 或利用 GPU 加速。
2. **无镀膜模式下的 Python 字典组装优化**：针对无镀膜系统，进一步减少 ctypes 回传数据组装为 Python 复杂数据结构的开销，使无镀膜场景的端到端耗时也能全面超越纯 NumPy 实现。
